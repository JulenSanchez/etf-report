## 一、Tuner 前端文本

### 顶部标签页

| 前端文本 | 含义 |
|---------|------|
| 回测工作坊 | 策略参数调优 + 回测运行 + 结果查看的主页面 |
| 数据管理 | 数据覆盖矩阵——每支 ETF × 每天一个单元格，查看数据完整性、拆股、停牌 |

### 回测工作坊 — 按钮

| 前端文本 | 含义 |
|---------|------|
| "刷新数据" | 盘中拉新浪实时价存入内存（不写 CSV），盘后拉新浪收盘价写入 CSV，并补历史缺口 |
| "运行回测" | 用当前面板参数跑一次完整回测，结果更新到右侧指标卡 |
| "盘中回测" | 勾选后运行回测会合并盘中实时价（而非只用 CSV 收盘价） |

### 回测工作坊 — 预设下拉框

| 前端文本 | 含义 |
|---------|------|
| gam-0 | 当前生产策略预设——F1=82% F7=18%（两因子），w3=0（F3 已退役），MH=2，固定日调仓 |

### 回测工作坊 — 参数面板（节选）

| 前端文本 | 含义 |
|---------|------|
| 最大持仓 (MH) | 策略最多同时持有几支 ETF |
| 调仓频率 | 固定日调仓（每天）还是周调仓 |
| F1 权重 (w1) | 趋势动量因子在总分中的占比 |
| F3 权重 (w3) | 成交量因子在总分中的占比（生产 preset gam-0 已退役=0%，其余 preset 保留） |
| F7 权重 (w7) | 短期反转因子在总分中的占比 |
| 分数带 (B) | 新标的替换旧持仓时，分数优势必须超过的阈值，防止频繁换仓 |
| MA 上方仓位 | 牛市时的目标杠杆 |
| MA 下方仓位 | 熊市时的目标杠杆 |
| C 灵敏度 | 仓位集中度的动态调节强度 |

### 回测工作坊 — 结果卡片

| 前端文本 | 含义 |
|---------|------|
| 年化收益 (AR) | 折算到一年的平均收益率 |
| 最大回撤 (MDD) | 历史净值从峰顶到谷底的最大跌幅 |
| 夏普比率 | 每单位波动换来的超额收益（越高越好） |
| 索提诺比率 | 只看下行波动的风险调整收益 |
| 卡玛比率 | AR ÷ MDD，每 1% 回撤的年化回报 |
| NAV | 假设初始投入 100 万的当前净值 |
| 最终持仓 | 回测最后一天的调仓结果：买了哪几支、各占多少比例 |

## 二、控制台输出

"刷新数据"按钮点击后会打印以下文本：

| 控制台输出 | 含义 |
|-----------|------|
| `Sina收盘 \| 54+4 OK, 0 fail` | 盘后：新浪一次拿到 58 支（54 交易 ETF + 4 基准 ETF）的确认收盘价，全部写入 CSV |
| `Sina实时 \| 54+4 ETFs` | 盘中：新浪拿到 58 支的实时价，存入内存供回测使用 |
| `Tencent实时 \| 54+4 ETFs` | 盘中：新浪不可用时，改用腾讯拿到实时价（远端 CI 环境常见） |
| `Tencent增量 \| 54+4 OK, 0 fail` | 历史缺口补拉：用腾讯 API 逐支补上 CSV 缺失的日期 |
| `[Refresh]` | 数据刷新步骤的日志前缀 |
| `[Intraday] Sina returned empty, trying Tencent fallback...` | 盘中：新浪实时价拉取失败，自动切换腾讯 |

## 三、DM 面板（数据管理）

### 按钮

| 前端文本 | 含义 |
|---------|------|
| "补全空缺" | 逐日比对交易日历和 CSV，用腾讯 API 补齐缺失日期的数据 |
| "强制更新" | 忽略新鲜度标记，重新拉取指定 ETF 的全量或增量数据 |
| "删除选中" | 删除 CSV 中选中日期的行（日线模式删除该日；周线模式删除该周对应日期段的日线后重建周线） |
| "下载 CSV" | 下载选中 ETF 的 CSV 文件到本地 |

### 频率切换

| 前端文本 | 含义 |
|---------|------|
| 日线 | 按天显示数据覆盖状态 |
| 周线 | 按周显示数据覆盖状态（从日线聚合） |
| 因子 | 显示各 ETF 的因子缓存状态 |

### 单元格颜色

| 前端颜色 | 含义 |
|---------|------|
| 绿色 | CSV 有该日期的完整数据 |
| 黄色 | 盘中实时价（尚未写入 CSV，盘后写入） |
| 深色（"缺失"） | CSV 无该日期 + 无盘中实时价 |
| 红色（"暴跌 >25%"） | 单日跌幅超过 25%，标记异常待检查 |
| 橙色（"暴涨 >25%"） | 单日涨幅超过 25%，标记异常待检查 |

### 单元格标记

| 前端文本 | 含义 |
|---------|------|
| ⚠ | 检测到拆股事件（如 1 拆 2），历史价格需按比例修复 |
| "数据不足" | 该 ETF 的历史数据天数不够，无法计算因子 |
| "盘中实时"（图例） | 该列是今天，数据来自新浪/腾讯实时行情，非 CSV |

## 四、信号推送

| 推送中的文本 | 含义 |
|-------------|------|
| `XX/XX 赌徒 调仓信号` | 本地 PC 定时推送的信号表标题 |
| `XX/XX 赌徒 调仓信号 (远端)` | GitHub Actions 远端兜底推送（PC 故障时自动接管） |

### 信号表内容

| 推送中看到的 | 含义 |
|-------------|------|
| 目标 % | 该 ETF 在总资金中的目标占比 |
| 价格 | 当前盘中价（远端推送时为盘中实时价；拉不到盘中价时为最近收盘价） |
| 金额/股数 | 按 50-60w 总投入算出的买卖金额和股数（11 档） |
| Server酱 | 微信推送通道——信号通过它发到手机 |

## 五、代码交叉引用（仅 AI）

> 此节不用于与用户沟通。反向索引：从代码查前端文本。

### 数据刷新链路

| 代码 | 对应前端 |
|------|---------|
| `refresh_data()` | "刷新数据"按钮的完整流程 |
| `_fetch_sina_realtime(cfg)` | 新浪行情拉取（→ 控制台 `Sina实时` / `Sina收盘`） |
| `_fetch_tencent_realtime(cfg)` | 腾讯实时行情拉取（→ 控制台 `Tencent实时`） |
| `_sina_batch_append(cfg, date, rt)` | 盘后快写：一次性写 58 支 ETF 收盘价到 CSV（→ `Sina收盘`） |
| `_populate_intraday_cache(cfg, now, date, time)` | 盘中实时入缓存（→ `Sina实时` / `Tencent实时`） |
| `_run_incremental_fetch(cfg)` | 历史缺口补拉——交易 ETF（→ `Tencent增量`） |
| `_get_daily_with_cache(code)` | 日线合并：CSV 收盘价 + 盘中实时价 |
| `_get_benchmark_daily_with_cache(code)` | 基准日线合并：同上，针对四支基准 ETF |
| `CACHE["intraday_cache"]` | 盘中缓存——内存中的当日实时价 |
| `CACHE["all_daily"]` | 全量日线缓存——内存中的完整日线 |
| `FRESH_MARKER` (`.fresh_today`) | 新鲜度标记——今天是否已拉过数据 |
| `_latest_allowed_date(now)` | 数据安全日期——盘中=昨天，盘后=今天 |
| `COOL_OFF_TIME` (15:10) | 收盘冷却时间——15:10 前禁止写 CSV |

### 历史术语

| 术语 | 含义 |
|------|------|
| 拆股 | ETF 份额拆分（如 1:2、1:3），拆前价格需等比缩放至拆后基准 |
| 前复权（qfq） | 腾讯 API 参数，自动将历史价格按最新拆股比例调整 |
| 内存清洗（bridge） | 拆股临时补偿：比对 CSV 末笔收盘价 ÷ 实时价 ≈ 拆分比例 → 内存中历史价格同步缩放 |
| 全量重拉 | `--full` 模式重新拉取 ETF 全部历史 K 线，拆股后永久修复用 |
| 残量吸收 | 末位 ETF 吸收所有剩余购买力，确保资金不闲置 |
| 牛熊切换纠偏 | 牛/熊切换时目标杠杆大幅跳变，引擎执行大规模买卖追到新目标 |
| 超涨 | F7 语境：近期累计涨幅显著高于历史均值（涨过头），F7 压分 |
| 超跌 | F7 语境：近期累计跌幅显著低于历史均值（跌过头），F7 加分 |
| 盘后定价交易 | 15:05-15:30 以收盘价固定价格成交，覆盖全部 A 股+ETF |
| 昨天 / 今天 | 口语表述 → 系统自动转为交易日语义 |

1. **Tuner 前端文本新增/修改** → 必须同步更新本表第一节或第三节
