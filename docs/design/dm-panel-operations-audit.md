# DM 面板操作审计 — 删除/强制更新/补全空缺 × 数据层 × 字段

**日期**: 2026-07-27 | **触发**: 用户发现周线模式删除会连带删除日线数据

## 数据层与字段说明

DM 面板有两级筛选器：

| 层级 | 选项 | 数据源 | 备注 |
|------|------|--------|------|
| **数据层** (dmFreq) | 日线 / 周线 / 因子 | CSV / CSV / factor_cache pickle | 决定日期列和删除目标 |
| **字段** (dmField) | 收盘价 / 成交量 / 成交额（日线周线）；F1 / F3 / F7（因子） | 同一 CSV 不同列 / pickle 不同 key | 只影响单元格**显示值**，不影响操作 |

**关键前提**：
- 字段切换（收盘价→成交量）**只改变单元格里的数字**，不改变日期列、不改变 cell key（永远是 `code|date`）
- 数据层切换（日线→周线）**改变日期列和 cell key 中的 date 值**
- 选中格子的 key 格式始终为 `"code|date"`，date 来自当前数据层的日期列

## 前端 → 后端路由表

| 操作 | 因子模式 | 周线模式 | 日线模式 |
|------|---------|---------|---------|
| **删除选中** | ⚠️ 无特殊处理，走通用逻辑 | 走通用逻辑 → `/api/data_delete` | 走通用逻辑 → `/api/data_delete` |
| **强制更新** | `dmDeleteCache()` → `/api/factor_cache_delete` | `freq='weekly'` → `/api/data_refetch` | `freq='daily'` → `/api/data_refetch` |
| **补全空缺** | `dmRebuildCache()` → `/api/factor_cache_rebuild` | `freq='weekly'` → `/api/data_fill_gaps` | `freq='daily'` → `/api/data_fill_gaps` |

## 各数据层 × 各字段 × 各操作的实际效果

### 一、删除选中

| 数据层 | 字段 | 发送的日期 | 后端实际操作 | 结果 | 判定 |
|:--:|------|------|------|------|:--:|
| 日线 | 收盘价 | 日线日期（如 2026-07-15） | 删日线 CSV 中该日行 → 重建周线 | 日线行消失，对应周重建 | ✅ |
| 日线 | 成交量 | 同上 | 同上 | 同上 | ✅ |
| 日线 | 成交额 | 同上 | 同上 | 同上 | ✅ |
| **周线** | 收盘价 | 周线日期（如 2026-07-18 周五） | 删日线 CSV 中匹配日期的行 → 重建周线 | 删了日线的那一天 + 整周被重建 | ❌ |
| **周线** | 成交量 | 同上 | 同上 | 同上 | ❌ |
| **周线** | 成交额 | 同上 | 同上 | 同上 | ❌ |
| **因子** | F1 | 因子日期（=日线日期） | 删日线 CSV → 重建周线 → **因子缓存未清** | 日线/周线被删，因子缓存残留 | ❌❌ |
| **因子** | F3 | 同上 | 同上 | 同上 | ❌❌ |
| **因子** | F7 | 同上 | 同上 | 同上 | ❌❌ |

**核心 bug**：
1. **周线模式**：后端 `api_data_delete` 永远操作 `{code}_daily.csv`，无视前端当前模式。周线日期传给后端后被当作日线日期处理。
2. **因子模式**：`dmDeleteSelected()` 无因子模式检测（对比 `dmRefetchSelected` 和 `dmFillGaps` 都有 `if (dmFreq === 'factor')` 分支），直接走通用删除逻辑。

### 二、强制更新

| 数据层 | 字段 | 后端操作 | 结果 | 判定 |
|:--:|------|------|------|:--:|
| 日线 | 收盘价 | 删区间→Tencent 增量拉取→写日线 | 日线区间被覆盖更新 | ✅ |
| 日线 | 成交量 | 同上 | 同上 | ✅ |
| 日线 | 成交额 | 同上 | 同上 | ✅ |
| **周线** | 收盘价 | **从日线全量重建周线（不联网）** | 周线被覆盖，但依赖日线完整性 | ✅ |
| **周线** | 成交量 | 同上 | 同上 | ✅ |
| **周线** | 成交额 | 同上 | 同上 | ✅ |
| 因子 | F1 | 删因子缓存文件 | 缓存消失，下次回测自动重建 | ✅ |
| 因子 | F3 | 同上 | 同上 | ✅ |
| 因子 | F7 | 同上 | 同上 | ✅ |

**评估**：强制更新在各模式下逻辑正确。周线模式的设计意图是"周线是日线的派生数据，不需要单独拉取"——这是合理的。

### 三、补全空缺

| 数据层 | 字段 | 后端操作 | 结果 | 判定 |
|:--:|------|------|------|:--:|
| 日线 | 收盘价 | 检测日线缺口 → Tencent 逐支补拉 | 缺失日线被补齐 | ✅ |
| 日线 | 成交量 | 同上 | 同上 | ✅ |
| 日线 | 成交额 | 同上 | 同上 | ✅ |
| **周线** | 收盘价 | 检测周线缺口 → **从日线重建周线** | 假设日线完整；若日线也有缺则周线仍然缺 | ⚠️ |
| **周线** | 成交量 | 同上 | 同上 | ⚠️ |
| **周线** | 成交额 | 同上 | 同上 | ⚠️ |
| 因子 | F1 | 从日线重新计算因子 → 写缓存 | 缓存被覆盖 | ✅ |
| 因子 | F3 | 同上 | 同上 | ✅ |
| 因子 | F7 | 同上 | 同上 | ✅ |

**评估**：周线补全的"从日线重建"逻辑正确，但**不先检查日线完整性**。如果日线本身有缺口，重建的周线也会缺。应先在日线层补缺口，再重建周线。

## 应然行为

| 数据层 | 删除选中 | 强制更新 | 补全空缺 |
|:--:|------|------|------|
| **日线** | 删除日线 CSV 行 → 重建周线 | 覆盖式重拉日线 | Tencent 补日线缺口 |
| **周线** | 删除日线 CSV 对应周的**全部日线** → 重建周线 | 从日线重建周线 | **先补日线缺口 → 再重建周线** |
| **因子** | 删除因子缓存 | 删除因子缓存 | 重建因子缓存 |
