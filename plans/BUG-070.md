# BUG-070: AUM 补拉依赖丢失的临时模块 `_working/fetch_aum_ttjj.py`

**严重度**: 🟡 Medium | **状态**: fixed | **发现日期**: 2026-09-14 | **关闭日期**: 2026-09-15

## 现象

跑 `python scripts/scan_etf_universe.py --dry-run`，日志出现：

```
Fetching AUM for 55 ETFs...
  [WARN] AUM fetch failed: No module named '_working' — 55 ETFs have AUM=0
```

55 支通过成交额过滤、但不在 `step3_aum.json` 缓存里的 ETF，AUM 补拉静默失败，`mcap_yi=0`。影响 `etf_score` 的 15% 规模权重（log10(aum) 掉到兜底值 0.01）和 Sheet5 评级。

## 根因

`scan_etf_universe.py:139` 硬依赖临时模块：

```python
from _working.fetch_aum_ttjj import fetch_batch as _aum_fetch
```

`_working/fetch_aum_ttjj.py` 是临时脚本，**从未 commit 进 git**，被 skill-sanitization 清理后留下悬空引用。根因是「筛选流正式脚本依赖了一个会被清理的临时模块」，不是数据源本身的问题。

## 修复方案

把 AUM 补拉从「依赖 `_working` 临时模块」改为「复用 `fetch_etf_metadata.py::fetch_aum`」——这是 REQ-213 交付的正式模块（东财净资产规模，返回亿元），已在维护、不会被清理，且 `scan_etf_universe.py` 本身已 import 它的 `fetch_one` 补 holdings。

- 移除 `_working` 依赖。
- 逐支调用 `fetch_aum(code)`，每支 sleep 0.5s 防反爬（55 支 ≈ 30s，可接受）。
- 已实测可用：`fetch_aum('510050')=196.98` 亿、`fetch_aum('512400')=224.89` 亿，口径与 `_spot_map`（亿元）一致。
- 失败降级不阻塞：单支返回 `None` 跳过（维持现有「AUM=0 走过滤」语义，但改为暴露单支失败而非整批静默）。

## 影响面

- 仅改 `scripts/scan_etf_universe.py` 的 AUM 补拉段（约 10 行）。
- 不涉及数据源切换、不涉及 `step3_aum.json` 缓存格式。

## 验收方式

| # | 验证项 | 方法 | 通过标准 |
|---|--------|------|---------|
| 1 | 无悬空引用 | 跑 `python scripts/scan_etf_universe.py --dry-run` | 日志**不再出现** `No module named '_working'` |
| 2 | 补拉成功 | 同上 | 日志出现「Fetched N AUM records」（N>0），替代「55 ETFs have AUM=0」 |
| 3 | 数量级合理 | 抽查 1-2 支此前 AUM=0 的 ETF | `mcap_yi` 非零且为亿元级（如几亿~几百亿） |
