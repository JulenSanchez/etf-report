# REQ-397: 盘后报告迁移到 GitHub Actions

**优先级**: 🔴 P0 | **状态**: in_progress | **目标版本**: v3.15.0 | **依赖**: 无 | **创建日期**: 2026-08-07

## 动机

当前盘后报告（16:00 CST）依赖 Windows 计划任务 + stable 仓库，存在三个问题：

1. **PC 依赖**：电脑关机/断网 → 报告不更新，GitHub Pages 停留在旧数据
2. **stable 仓库污染**：`daily_report.bat` 生成 `index.html` / `runtime_payload.js` / `quant_payload.js` 后留在 stable 工作区变成 uncommitted 改动
3. **双仓维护**：main 开发 → stable 同步的流程，报告数据流是反的（stable 产生数据但应回 main）

将盘后报告迁移到 GitHub Actions，让远端执行数据拉取 → 报告生成 → Pages 发布全流程。

## 现有逻辑确认

### Windows 计划任务

```
任务名: etf盘后报告
触发时间: 16:00 CST, 每周一至周五
脚本: C:\Users\julentan\etf-report-stable\batchfiles\daily_report.bat
```

### daily_report.bat 流程

```bat
1. chcp 65001 (UTF-8)

3. 检查交易日 → 非交易日退出

5. python scripts\update_report.py --publish    # 报告生成 + 企微通知 + GitHub Pages 部署
```

## 迁移方案

### GitHub Actions Workflow

```yaml
触发: cron '30 8 * * 1-5' (08:30 UTC, 周一至周五) + workflow_dispatch
环境: ubuntu-latest, Python 3.11
超时: 30 min

步骤:
1. checkout main 分支
2. pip install -r requirements.txt
3. 检查交易日 → 非交易日跳过
4. cache restore data/quant/
5. git config (user.name/user.email)
6. python scripts/update_report.py --publish
7. cache save data/quant/
```

### 与本地执行的关键差异

| | 本地 stable | GitHub Actions |
|---|---|---|
| 触发 | Windows Task Scheduler 16:00 CST | cron 08:30 UTC (约16:30+ CST) |
| 数据 | 本地 CSV 累积 | cache restore 持久化 |
| Tuner | Flask :5180 (stable 端口) | Flask :5179 (默认端口) |
| git push | SSH key | GITHUB_TOKEN |
| 提前检查 | 先跑 quant_data_fetcher 再 update_report | 直接跑 update_report（内含 Step 2.6） |

### 不需要改的

- `update_report.py` 本身不改 — 已有跨平台 `_ensure_tuner()` 和 `--publish` 模式
- `deployer.py` 不改 — `repo_root: ""` 自动解析为当前 git 仓库
- 本地 Windows 计划任务暂时保留，待验证通过后再移除

## 验证

1. `workflow_dispatch` 手动触发，确认全流程通过（日志可见每步输出）
2. 确认 GitHub Pages 报告日期更新为当天
3. 确认 git 提交记录中出现 `data: ETF daily report update - {date}`
4. 确认稳定运行 3 个交易日
5. 验证通过后：删除 Windows 计划任务 `etf盘后报告` + 删除 `daily_report.bat`
