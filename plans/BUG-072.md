# BUG-072: 筛选流生成 xlsx 无差别强杀全部 Excel（含未保存工作）

**严重度**: 🟡 Medium | **状态**: fixed | **发现日期**: 2026-10-12 | **关闭日期**: 2026-10-12

## 现象

跑 `python scripts/scan_etf_universe.py --debug` 生成 debug xlsx 时，日志出现：

```
成功: 已终止进程 EXCEL.EXE 其 PID 为 21412
```

脚本会无差别 `taskkill /f /im excel.exe`，杀掉系统里**所有** Excel 进程（含用户正在编辑、尚未保存的表格），随后自动打开新 xlsx。

## 根因

`scan_etf_universe.py:1019` 硬编码：

```python
os.system('taskkill /f /im excel.exe 2>nul')
import time; time.sleep(1)
wb.save(str(OUTPUT))
```

开发者意图是避免 openpyxl 保存 xlsx 时文件被 Excel 锁定（`PermissionError`），但实现是「无差别强杀全部 Excel」而非「只释放这一个文件」。`/f` 强制杀进程、不保存未保存工作，副作用是用户其他 Excel 工作丢失。

## 修复方案

去掉 `taskkill`，改为「保存失败时明确报错暴露」：

- 删除 `os.system('taskkill /f /im excel.exe 2>nul')` 和 `import time; time.sleep(1)`。
- `wb.save(str(OUTPUT))` 包 `try/except PermissionError`，失败时打印明确提示（文件被 Excel 占用，请关闭后重跑），`sys.exit(1)`。
- 保留保存成功后的 `start excel` 自动打开（便利、无害）。

## 影响面

- 仅改 `scripts/scan_etf_universe.py` 的 [DEBUG] 生成 xlsx 段（约 5 行）。
- 不涉及数据源、筛选、分类逻辑。

## 验收方式

| # | 验证项 | 方法 | 通过标准 |
|---|--------|------|---------|
| 1 | 不再杀 Excel | 跑 `python scripts/scan_etf_universe.py --debug` | 日志无 `taskkill`/`已终止进程` 输出，其他 Excel 进程不被杀 |
| 2 | 正常保存 | 同上 | 出现 `Saved: ...etf_screening_debug.xlsx`，退出码 0 |
| 3 | 占用报错（暴露失败） | 先用 Excel 打开 xlsx 再跑 --debug | 打印 `[ERROR] 无法写入...文件正被 Excel 占用`，退出码 1，不杀 Excel |
