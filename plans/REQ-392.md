# REQ-392: 术语表分层治理 — 消除 AI-用户沟通中的代码符号

**优先级**: 🔴 P0 | **状态**: done | **目标版本**: v3.15.0 | **依赖**: 无 | **创建日期**: 2026-07-24

## 动机

2026-07-24 会话评审发现：AI 在沟通中大量使用代码级符号（函数名 `_build_ma_trend_cache`、变量名 `intraday_cache`、脚本名 `preclose_push.py`）替代用户语言（"MA 趋势计算"、"盘中缓存"、"收盘前推送"）。用户需要的是用 Tuner 界面上存在的按钮名、DM 面板的标签、通俗的功能概念来沟通——而不是追踪代码路径。

现存 `docs/design/glossary.md` 有 53 个术语条目，但全部偏向代码/研究视角（"分栏取样"、"缩界"、"残量吸收"），缺少"用户操作 → 功能概念 → 代码实现"的映射层。

AGENTS.md 已有原则（"用中文描述，不用函数名"、"对话末尾检查术语表"），但缺乏术语表支撑就无法执行。

## 范围

### Phase 1: 术语表补全（立即可做）

新增三类术语条目：

**A. 用户操作 → 功能概念**

| 用户看到的/点的 | 概念名 | 一句话解释 |
|---------------|--------|-----------|
| "刷新数据"按钮 | 数据刷新 | 根据当前时间自动选数据源（盘中=Sina 实时价，盘后=Sina 收盘价写 CSV），并补历史缺口 |
| "补全空缺"按钮 | 缺口修复 | 逐日比对交易日历和 CSV，用腾讯 API 补缺失日期 |
| "强制更新"按钮 | 强制重拉 | 忽略新鲜度标记，重新拉取指定 ETF 的全量或增量数据 |
| "数据管理"页面 | DM 面板 | 数据覆盖矩阵——查看每支 ETF 每天的数据状态，检测缺口、拆股、停牌 |
| "回测工作坊"页面 | Tuner 界面 | 策略参数调优 + 回测运行 + 结果查看的主界面 |
| "运行回测"按钮 | 回测执行 | 用当前参数跑一次完整回测 |
| "刷新数据" → 控制台输出 `Sina收盘` | 盘后快写 | Sina API 一次性拿到 58 支 ETF 的确认收盘价并写入 CSV |
| "刷新数据" → 控制台输出 `Sina实时` | 盘中实时 | Sina API 拿到 58 支 ETF 的实时价存入内存（不写 CSV） |
| "刷新数据" → 控制台输出 `Tencent增量` | 历史缺口补拉 | 腾讯 API 逐支拉取 CSV 中缺失日期的数据 |

**B. 数据源 → 通俗名**

| 代码里的名字 | 概念名 | 一句话 |
|-------------|--------|--------|
| Sina API (hq.sinajs.cn) | 新浪行情 | 一次 HTTP 拿全部 ETF 实时价/收盘价，快（~2s），盘中盘后都用 |
| Tencent API (web.ifzq.gtimg.cn) | 腾讯行情 | 逐支 ETF 拉历史日线，慢（~1min/全池），用于补历史缺口 |

**C. 数据流 → 概念名**

| 代码路径 | 概念名 | 一句话 |
|---------|--------|--------|
| `_get_daily_with_cache` / `CACHE["all_daily"]` + `intraday_cache` 合并 | 日线合并 | 回测取价的标准路径：CSV 历史收盘价 + 盘中实时价（如有） |
| `_get_benchmark_daily_with_cache` | 基准日线合并 | 同上，但针对 510050/510300/510500/159915 四支基准 ETF |
| `_sina_batch_append`（盘后快路径） | 盘后快写 | 盘后一次性将 58 支 ETF 的确认收盘价写入 CSV |
| `_run_incremental_fetch`（Tencent 增量） | 历史缺口补拉 | CSV 有缺失日期时，逐支通过腾讯 API 补齐 |
| `_populate_intraday_cache`（盘中实时路径） | 盘中实时入缓存 | Sina 拉取实时价后写入 Tuner 内存，回测时临时合并 |
| `CACHE["intraday_cache"]` | 盘中缓存 | Tuner 内存中存的当天实时价，不写 CSV，回测时合并到日线 |
| `FRESH_MARKER` (`.fresh_today`) | 新鲜度标记 | Tuner 记录"今天已经拉过数据"的标记文件，防止重复拉取 |
| `_latest_allowed_date` / `latest_allowed_close_date` | 数据安全日期 | 盘中返回昨天（不碰未完成的 K 线），盘后返回今天 |
| `COOL_OFF_TIME` (15:10) | 收盘冷却时间 | 15:10 之前禁止写 CSV（确保拿到的是确认收盘价而非盘中价） |

### Phase 2: 术语表分层重构（中期）

将 glossary.md 按三个视角重新组织：

1. **用户层**：按钮名、界面标签、用户日常看到的文本
2. **概念层**：功能名、数据流名、设计决策名（AI 与用户沟通的标准语言）
3. **代码层**：函数名、变量名、文件名（仅作交叉引用，不作为沟通语言）

AI 沟通规则：与用户沟通时用**概念层**，读代码时用**代码层**。两层的映射关系记录在术语表中。

### Phase 3: AGENTS.md 术语表检查点（长期）

在 AGENTS.md 增加：

1. **对话中触发检查**：AI 用了函数名/变量名来解释功能 → 必须问"要不要加入术语表"
2. **对话末尾检查**：AGENTS.md 已有此条（"对话末尾检查术语表"），但缺乏具体执行步骤。补：列出本次对话出现的未收录术语 → 用户确认 → 写入 glossary.md
3. **UI 标签变更时联动**：改动了 Tuner 控制台/前端显示的文本标签 → 必须同步更新 glossary.md 中对应的用户层条目

## 技术方案

- 改动文件：`docs/design/glossary.md`（主要）、`AGENTS.md`（检查点补充）
- 改动类型：文档重构 + 规则补充
- 不改代码，不跑测试
